Sync Gateway, Server And The Operator

Sync Gateway 4.1

Access by channel

A channel per store, enforced by a sync function: a store writes only what it signed and reads only its own channel.

Couchbase Server 8.0

One place for the fleet

Bucket fleet, scope a2a, the same collections: the whole fleet’s history, kept and queryable.

Autonomous Operator on k3d

One command

cargo xtask fleet-up builds a local cluster with one Server node and Sync Gateway, in about 2 GB of memory.

Why a gateway. A head office dialling every store peer to peer needs a connection to each, with no per-store access rules. Between companies nothing changes: no company gets gateway access.

The sync function routes each document by the signer it names and refuses writes into another store’s channel; an approval is written by a duty manager’s node into a store’s channel and only if that node was given the channel. The head office has the role that may write documents no node signed, such as the authority’s revocations. Server and Sync Gateway run on a local k3d cluster under the Couchbase Autonomous Operator, as in the kubecondemo scenarios.
